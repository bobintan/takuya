# 候補者対応ルーティン（SCYLOG）

人材紹介（IT・コンサル領域）の担当CA 西川琢也さんの定型業務。
ユーザーが「いつも通り」と言ったら、該当フェーズの手順を**聞き返さずに全部**実行する。

## 前提（Google Drive）

- 候補者のルート：`Takuya Nishikawa / 候補者情報`（folderId `19KMI3MTyI7qvP98kn7HQWJVugz_V-Bt8`）
- 社内求人DB：`Takuya Nishikawa / 社内求人_自動検索用.xlsx`（fileId `1UNV4Wea6EcW-AqLm4kVVG9wMH-njVr_v`）
  - `download_file_content` → base64 デコード → pandas で読む（openpyxl が無ければ pip install）
  - `削除` 列が空の行だけを有効求人とする。企業名が空の行は、同じ `事業内容` の行から企業を推定し「推定」と明記
- 過去の型の参考：`20260929_小林純一` フォルダ（面談準備メモ、企業紹介doc、お礼メール）

## フェーズ1：面談準備（「これから面談します」＋プロフィール）

1. **候補者フォルダを作る**：`候補者情報/YYYYMMDD_氏名`（面談日・スペースなし）
   - サブフォルダ：`求人票/会社資料`、`レジュメ`、`議事録`
2. **ヒアリング項目・想定質問シート（Google Doc）**を候補者フォルダ直下に作る
   - 構成：0.3行サマリ／1.プロフィール（確定情報）／2.仮説（H1〜。確かめ方の質問つき、今日必ず取る仮説を明示）／3.ヒアリング項目チェックリスト（転職理由・軸・実績の数字・スキル・条件・活動状況）／4.質問リスト（台本順）／5.当日提示できる求人／6.想定反論と返し／7.面談前にやること／8.面談後にやること
   - ★＝未確認・面談で取る項目
3. **求人マッチング・ランキング（Google Doc）**を `求人票/会社資料` に作る
   - 絞り込み：勤務地（希望エリア／フルリモート）→職種・業界キーワード→年収レンジ→必須要件の充足度
   - 判定記号：◎強く推奨／○推奨／△条件次第／✕見送り。表＋個別評価＋見送り理由
   - DBに無い領域（例：大手メーカー・外資）があれば「DB外で開拓が必要」と明記
4. ユーザーが求人票PDF・テキストを追加で渡したら、必須要件を1つずつ突き合わせて判定し、全体ランキングを更新して返す
   - 画像だけのPDF（pdftotext で空）は pdftoppm で画像化→縦に分割して読む

## フェーズ2：面談後（「面談終わりました」）

1. Drive で `キャリア面談_氏名 ... Gemini によるメモ` を探し、**文字起こしを全文読む**（Geminiの要約だけで判断しない。固有名詞の誤変換に注意）
2. メモを `議事録/YYYYMMDD_初回面談_文字起こし` としてコピー
3. **候補者情報・転職活動情報サマリー（Google Doc）**を候補者フォルダ直下に作る
   - 構成：0.現在地（意欲点数・次アクション・保留）／1.ホットボタン（転職理由の層・希望条件・刺さった/刺さらなかった求人）／2.経歴／3.キャリア観／4.選考状況とCAの見立て／5.意思決定チェックリスト／6.次回論点／7.面談でCAが伝えた内容のうち要訂正・未確認のもの
   - 候補者が話した**現職の社内情報**は「取扱注意・社外転記禁止」と冒頭に書く
4. 次アクション（カジュアル面談調整・求人送付・LINE送付など）を一覧で返し、どちらから作るか聞く

## フェーズ3：求人送付（「求人入れたから進めて」「お礼メールと求人送付」）

### 候補者共有フォルダの作り方
- 候補者フォルダ内に **`氏名様_ご紹介求人・会社資料`** を作る（社内用の `求人票/会社資料` とは**別**。社内用にはランキング等の社内評価が入っているので絶対に共有しない）
- 企業ごとにサブフォルダ `NN_会社名`（NN＝おすすめ順の2桁番号）を作り、求人票PDF・会社資料・企業紹介docを入れる

### 判定と振り分けのルール（重要）
- **◎・○・△ の求人は候補者共有フォルダに入れる**（△＝条件次第も候補者に見せて判断材料にする）
- **✕（必須要件を満たさない）の求人は候補者共有フォルダに入れない**。社内側の `求人票/会社資料/90_見送り（必須要件未充足・氏名様非共有）` に移動する（削除はしない）
- 1社の中で判定が分かれる場合も同じ（例：同じ会社のLeader職は共有、Manager職で管理職経験必須のものは90_へ）
- 古い版のdocは消さず、`（旧版）` を付けて90_フォルダへ移す

### 企業紹介doc（各社サブフォルダに1つ）
- タイトル：`会社名_企業紹介（氏名様向け）`
- 構成：【1】一言でいうと／【2】会社の基本情報／【3】事業の中身／【4】ご紹介ポジション（年収・勤務地・必須要件の表）／【5】氏名様に合いそうな点（必須要件と経歴の突き合わせ）／【6】確認しておきたい点（年収内訳・固定残業・出社頻度・選考フロー・未確認事項）／【7】カジュアル面談で聞くとよい質問／【8】出典
- 候補者に渡す文書なので、社内評価（◎○△の記号、他候補者の情報、推薦の駆け引き）や現職の社内情報は書かない。△の求人は「確認が必要な点」として丁寧に書く
- 数字は求人票・公式発表で裏付けが取れたものだけ書く。取れないものは「確認中」と書く

### お礼＋求人送付メール（Gmail下書き）
- 宛先：候補者の個人アドレス／CC：`clients@hrjpn.com`。可能なら過去の面談調整メールのスレッドに返信する形
- 構成（小林純一様あての 2026/9/29・9/30 メールと同じ型）：
  1. お礼
  2. ■本日の面談まとめ（【本日お伺いした内容】【今後の方向性としてすり合わせた内容】）
  3. ■ご紹介求人について（共有フォルダURL＋各社1〜3行。番号はフォルダと一致させる）
  4. ■ご覧いただいた後のお願い
  5. ■カジュアル面談の候補日依頼（該当時）
  6. ■ご確認させていただきたいこと
  7. ■お送りいただいた書類について（修正点があれば角を立てずに）
  8. ■LINEのご登録について（https://lin.ee/2hY72tI）
  9. 署名（西川琢也／SCYLOG株式会社 の定型署名）
- 面談まとめには候補者が話した社内の内部情報（人員削減・システム障害など）を書かない
- 面談中にCAが口頭で伝えた内容に誤り・未確認があれば、メール内でさりげなく「資料の記載を正としてください」と訂正する
- **送信はしない**。下書き作成までで止め、ユーザーに確認を依頼する

## 共通ルール

- 外部公開になる操作（フォルダのリンク共有設定、メール送信）は行わず、ユーザーに依頼する
- 自分が以前に「未確認」と書いた事実が後で裏付けられたら、自分から訂正を伝える
- 完了報告では、作ったもののリンク、要確認事項、ユーザーに手作業してほしいことを短くまとめる
